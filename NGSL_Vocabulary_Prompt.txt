
NGSL 1.2 英语词汇学习工具

一、项目目标

请实现一个纯前端、单页面、无第三方依赖的 NGSL 1.2 英语词汇学习工具。

目标不是制作一个普通的 CSV 表格查看器，而是制作一个适合长期背诵、浏览、筛选、随机复习和维护个人生词状态的词汇学习工具。

要求：

一个独立的 index.html

CSS、JavaScript 全部内嵌

不使用任何第三方 JS/CSS 框架或 CDN

可以直接部署到 GitHub Pages 等静态服务器

不需要后端

NGSL 主数据从服务器加载

用户自己的生词状态保存在浏览器本地

页面刷新后状态保持

清除网站本地数据后，可以重新从服务器的默认生词文件初始化



---

二、核心数据架构：必须严格解耦

整个程序必须把以下三个概念完全分开：

1. NGSL 主词库

文件：

NGSL.json

下面是此文件内容的示例：
[
  {
    "Rank": "1",
    "Word": "the",
    "Word forms": "",
    "Pronunciation": "/ði/",
    "POS": "det",
    "Definition_ZH": "这",
    "Definition_EN": "used to refer to something already mentioned",
    "Level": "A1",
    "SFI": "87.85",
    "U Value": "60910"
  },
  {
    "Rank": "2",
    "Word": "be",
    "Word forms": "am, are, aren't, been, being, beings, is, isn't, was, wasn't, were, weren't",
    "Pronunciation": "/bi/",
    "POS": "verb",
    "Definition_ZH": "是",
    "Definition_EN": "To exist; to be alive; used to give information about someone or something",
    "Level": "A1",
    "SFI": "86.86",
    "U Value": "48575"
  }
]
它是固定、只读的 NGSL 1.2 词库数据。

NGSL 1.2 共 2809 个词条，Rank 为：

1 ～ 2809

每个 Rank 唯一，并且与一个词条永久绑定。

例如：

Rank 1 → the
Rank 2 → be
Rank 3 → and
...
Rank 2809 → thirst

Rank 是词条本身的一部分，不是当前页面序号。

网页绝对不能尝试修改服务器上的 NGSL_Unknown.txt。

三、Rank 的绝对规则

这是本项目最重要的规则之一。

Rank：

唯一；

稳定；

与 Word 一一绑定；

永远不能修改；

永远不能重新编号；

不因筛选改变；

不因搜索改变；

不因分页改变；

不因排序改变；

不因随机改变；

不因选择模式改变；

不因标记改变。


例如随机后可以显示：

147  alternative
3    and
82   achieve
1    the

但是 Rank 仍然是：

147
3
82
1

绝对不能变成：

1
2
3
4

这里的 Rank 应该被理解为：

> NGSL 词条的永久身份证。



程序内部建议直接使用：

rank

而不是容易产生歧义的：

id

不要把当前显示位置称为 Rank。

四、NGSL 主数据格式

优先使用：

NGSL.json

因为主词库是固定数据，JSON 比 CSV 更适合作为网页直接读取的数据格式。

推荐结构：

[
  {
    "rank": 1,
    "word": "the",
    "forms": "",
    "pron": "...",
    "pos": "article",
    "def_zh": "...",
    "def_en": "...",
    "level": "A1",
    "sfi": 99.99,
    "u_value": null
  }
]

字段：

rank
word
forms
pron
pos
def_zh
def_en
level
sfi
u_value

其中：

rank：Number

word：String

forms：String

pron：String

pos：String

def_zh：String

def_en：String

level：String

sfi：Number|null

u_value：Number|null


不要再在 NGSL 主文件中保存 Known 字段。

因为 Known/Unknown 属于用户状态，不属于固定词库数据。


---

五、如果实际仍使用 CSV，必须正确处理 CSV

如果项目最终采用 NGSL.csv 而不是 JSON，则：

必须支持真正的标准 CSV。

本项目实际 CSV 是：

> 英文逗号 , 作为字段分隔符。



不是制表符。

因此不能因为看到某些中文内容就错误地判断成 TSV。

必须实现标准 CSV parser，正确支持：

英文逗号 ,

双引号字段

"" 转义

字段内部包含逗号

字段内部包含换行

UTF-8

UTF-8 中文

BOM


例如：

1,"word","form1, form2","中文释义","English definition"

如果字段内部出现英文逗号，必须依靠标准 CSV 引号规则解析，而不是简单执行：

line.split(',')

严禁使用简单 split(',') 作为标准 CSV 解析器。

如果数据最终确定转换为 JSON，则直接使用 JSON，避免 CSV 解析问题。

六、Unknown 初始化机制

第一次打开网页时：

1. 加载 NGSL.json


2. 检查浏览器中是否已经存在用户 Mark 数据


3. 如果不存在，则加载：



NGSL_Unknown.txt

4. 将其中的单词转换成对应的 Rank


5. 建立用户初始 Mark 集合


6. 保存到 localStorage



例如：

NGSL_Unknown.txt

abandon
claim
alternative

程序找到：

abandon → rank 145
claim → rank 327
alternative → rank 147

最终用户本地保存的是稳定的 Rank：

[145, 327, 147]

推荐内部使用：

Set<number>

例如：

markedRanks = new Set([145, 327, 147]);


---

七、后续加载规则

如果用户已经拥有自己的 Mark 状态：

不要再次使用 NGSL_Unknown.txt 覆盖用户状态。

后续打开网页：

NGSL.json
+
localStorage Mark

直接恢复用户自己的状态。

只有当本地 Mark 不存在时，才使用：

NGSL_Unknown.txt

作为初始状态。


---

八、清除本地数据后的行为

如果用户清除该网站的 localStorage：

下一次打开：

NGSL.json
+
NGSL_Unknown.txt

重新初始化。

因此：

> 清除网站数据 = 恢复服务器提供的默认生词状态。

async function init() {
    loadTheme();
    loadPaginationPreference();
    loadLocalMark();

    bindEvents();

四十九、不要出现以下设计错误
